## 4. 공개 버전이 PC 본판과 다른 점 (중요)

`jeju_gw_dashboard_open` (공개 버전)은 `jeju_groundwater_dashboard` (PC 본판)와 의도적으로 다음 부분이 다릅니다. **PC 본판에서 새 코드를 가져올 때 이 차이를 깨뜨리지 않도록 주의**.

| 항목 | PC 본판 | 공개 버전 (이 폴더) | 이유 |
|---|---|---|---|
| `Quit` 버튼 (헤더 우측) | 있음 | **제거됨** | `os._exit(0)`이 Streamlit Cloud에선 무의미하고 위험 |
| `⚙️ 데이터 및 리포트` 탭 | 있음 | **제거됨** | xls 파싱 실행 버튼 등 외부 사용자가 누르면 안 되는 기능 |
| `🧾 분석 리포트` 탭 | (admin 탭에 통합) | **별도 탭으로 분리** | 리포트만 외부 사용자에게도 안전하게 노출 |
| `.gitignore` 데이터 제외 | 활성화 | **주석 처리** | 데이터를 GitHub에 포함시켜야 Streamlit Cloud가 읽음 |
| `.claude/` | (없음) | gitignore에 추가 | Claude Code 개인 설정 노출 방지 |
| API 키 읽기 | `.env`만 | `.env` 우선, 실패 시 `st.secrets` 폴백 | 로컬·Cloud 양쪽 호환 |

### 4.1 구체적으로 어디가 다른가

**`config.py`** (KMA_API_KEY 부분, 약 75번째 줄):
```python
KMA_API_KEY = os.getenv("KMA_API_KEY", "")
if not KMA_API_KEY:
    try:
        import streamlit as st
        KMA_API_KEY = st.secrets.get("KMA_API_KEY", "")
    except Exception:
        pass
```

**`src/dashboard/app.py`**:
- `import os` 제거 (Quit 버튼만 쓰던 것)
- 헤더 행에서 `dc_q` 컬럼과 Quit 버튼 코드 제거
- `tab4_admin` 임포트 주석 처리
- 탭 이름 5개 중 마지막을 `"🧾 분석 리포트"`로 변경
- `tabs[4]` 블록에 `tab_report.render(...)` 호출

**`src/dashboard/tabs/tab_report.py`** (새 파일):
- admin 탭의 리포트 생성 부분(Section D)만 추출

**`.gitignore`**: 데이터 제외 규칙들이 `#` 주석 처리됨. `.claude/` 추가됨.

> 💡 **PC 본판에서 새 기능 가져올 때**: 새 기능이 (1) 관리자만 써야 하는가? (2) 파일시스템에 직접 쓰는가? (3) API 키 외 시크릿이 필요한가? — 하나라도 해당하면 공개 버전에 그대로 옮기지 말고 변형하거나 제외할 것.

## 5. 초기 배포 절차 (이미 완료된 작업, 참고용)

> 이 섹션은 처음부터 다시 할 일이 생겼을 때만 참고. 이미 완료된 상태입니다.

### 5.1 코드 수정 (4번 섹션 참조)

위 4번 섹션의 차이점들을 적용.

### 5.2 GitHub에 첫 업로드

VSCode에서:
1. `C:\python\jeju_gw_dashboard_open` 폴더 열기
2. 좌측 사이드바 **분기 아이콘** 클릭 (또는 `Ctrl+Shift+G`)
3. **"GitHub에 게시"** 버튼 클릭
4. 브라우저로 GitHub 인증 → "Authorize Visual Studio Code" 클릭
5. **"Publish to GitHub public repository"** 선택
6. repo 이름 `jeju_gw_dashboard_open` Enter
7. (만약 git config 누락 에러 나면 PowerShell에서 3.3절 명령 실행 후 재시도)

만약 위 방법으로 안 되면 PowerShell:
```powershell
cd C:\python\jeju_gw_dashboard_open
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/jhson9/jeju_gw_dashboard_open.git
git push -u origin main
```

### 5.3 Streamlit Cloud 배포

1. https://share.streamlit.io 접속 → **"GitHub로 계속하기"**
2. "Authorize streamlit" 클릭
3. 우상단 **"Create app"** 클릭
4. **"Deploy a public app from GitHub"** 선택
5. 입력:
   - Repository: `jhson9/jeju_gw_dashboard_open`
   - Branch: `main`
   - Main file path: `src/dashboard/app.py`
   - App URL: `jeju-gw` (선택)
6. **"Advanced settings"** → Python version `3.11` → **Secrets** 박스에:
   ```toml
   KMA_API_KEY = "발급받은_API_키_값"
   ```
7. **"Deploy!"** 클릭 → 2~5분 대기 → 대시보드가 뜨면 성공

> ⚠️ Streamlit Cloud가 GitHub repo를 못 본다면(`This repository does not exist` 에러), repo가 Private이고 권한이 없는 상태일 수 있음 → repo를 Public으로 전환 (8.4절 참조).

## 7. 시크릿(API 키) 관리

### 7.1 Streamlit Cloud의 시크릿 변경
1. https://share.streamlit.io 접속
2. 본인 앱 카드의 우상단 **"⋮"** 메뉴 → **"Settings"**
3. 좌측 **"Secrets"** 탭
4. 텍스트 박스 수정:
   ```toml
   KMA_API_KEY = "새로운_API_키"
   ```
5. **"Save"** 클릭 → 약 1분 후 자동 반영 (앱 재시작)

### 7.2 새 API 키 발급이 필요할 때
- API 키 노출, 만료, 일일 호출 한도 초과 등의 사유.
- https://data.go.kr 로그인 → 마이페이지 → 인증키 발급 → "기상청_지상(종관, ASOS) 일자료 조회서비스" 신청
- 발급받은 새 키를 **두 곳 모두** 업데이트:
  1. 로컬 `.env` 파일
  2. Streamlit Cloud Secrets (위 7.1)

### 7.3 시크릿 보안 원칙
- ❌ `.env`, API 키를 **GitHub에 올리지 말 것** (.gitignore에 `.env` 등록되어 있는지 확인)
- ❌ 화면 캡처에 API 키가 보이는 채로 누군가에게 전송하지 말 것
- ✅ 의심스러우면 키 폐기·재발급이 가장 안전

## 8. 자주 발생하는 문제와 해결

### 8.1 "git에서 'user.name' 및 'user.email'를 구성해야 합니다" 에러
**원인**: 새 PC에서 git을 처음 쓸 때 발생.
**해결**: PowerShell에서 3.3절 명령 실행. 그 후 VSCode에서 다시 커밋 시도.

### 8.2 "fatal: 'origin' does not appear to be a git repository"
**원인**: 로컬 git 저장소에 GitHub 주소(remote)가 등록되지 않음.
**해결**: PowerShell에서:
```powershell
cd C:\python\jeju_gw_dashboard_open
git remote add origin https://github.com/jhson9/jeju_gw_dashboard_open.git
git push -u origin main
```

### 8.3 "GitHub repository already exists"
**원인**: 이전에 이미 같은 이름의 repo를 GitHub에 만들어둔 상태에서 다시 publish 시도.
**해결**: 이건 에러가 아니라 안내. 그냥 commit 후 **"동기화 변경 내용"**(Sync) 또는 8.2의 PowerShell `git push` 명령으로 push만 하면 됨.

### 8.4 Streamlit Cloud에서 "This repository does not exist" 빨간 에러
**원인**: repo가 Private이고 Streamlit이 접근 권한이 없음.
**해결 (간단)**: repo를 Public으로 전환
1. https://github.com/jhson9/jeju_gw_dashboard_open/settings 접속
2. 페이지 맨 아래 **"Danger Zone"** 섹션
3. **"Change visibility"** → **"Make public"** 선택
4. 체크박스 두 개 체크 → repo 이름 입력 → 빨간 버튼 클릭
5. Streamlit 페이지 새로고침

**해결 (Private 유지)**: https://share.streamlit.io 우상단 프로필 → Workspace settings → GitHub 재인증 → "All repositories" 선택

### 8.5 Streamlit Cloud 배포 중 빌드 실패
- 우상단 앱 카드 **"⋮" → "Manage app" → "Logs"** 에서 에러 확인
- 흔한 원인:
  - `requirements.txt`에 패키지 누락 → 추가 후 push
  - Python 버전 불일치 → Settings에서 변경
  - `.env`에만 있고 Secrets에 없는 환경변수 → Secrets에 추가

### 8.6 사이트는 뜨는데 `KMA_API_KEY 미설정` 같은 에러
**원인**: Streamlit Cloud Secrets에 API 키 누락 또는 형식 오류
**해결**: 7.1절 따라 Secrets 확인. 형식: `KMA_API_KEY = "값"` (따옴표 필수, `=` 양옆 공백)

### 8.7 push 시 인증 창이 자꾸 뜨거나 거부됨
**원인**: GitHub은 비밀번호 인증을 폐지함.
**해결**: 처음 한 번만 브라우저로 OAuth 인증("Authorize git-ecosystem"). 이후 자동 저장됨.

### 8.8 데이터 파일이 push 안 됨
**원인**: `.gitignore`에 데이터 제외 규칙이 활성화되어 있음.
**해결**: `.gitignore`에서 `data/ASOS/*.csv` 같은 줄들이 `#`으로 주석 처리되어 있는지 확인. 안 되어 있으면 4번 섹션 표 참조해서 주석 처리.

## 10. 무료 플랜 한계 및 주의사항

### 10.1 Streamlit Community Cloud 무료 플랜
- ✅ Public repo 무제한 배포
- ✅ Private repo 1개까지 배포
- ✅ 자동 HTTPS, 무료 도메인 (`.streamlit.app`)
- ⚠️ **앱 비활성 시 sleep**: 사용자가 며칠 안 들어오면 앱이 잠듬. 다음 첫 접속 시 30초~1분 깨어나는 시간 필요. 사용 빈도 낮은 데모이므로 큰 문제 아님.
- ⚠️ **자원 한계**: 1GB RAM, 동시 접속 ~100명. 본 프로젝트 규모(데이터 5MB, 시연 목적)에선 충분.
- ⚠️ 1GB repo 크기 제한 — 본 프로젝트는 ~5MB라 한참 여유.

### 10.2 GitHub 무료 플랜
- ✅ Public·Private repo 무제한
- ✅ 트래픽·저장공간 사실상 제한 없음 (개인 프로젝트 수준에서)
- ⚠️ Git LFS는 무료 1GB만 — 본 프로젝트는 LFS 안 씀.

### 10.3 향후 확장 시 고려사항
- 사용자 100명 이상 동시 접속 → Streamlit Cloud 유료 플랜 또는 Cloud Run 이전 검토
- 데이터 수십 MB 이상 → Firebase Storage 등 외부 저장소 검토
- 본인 도메인 사용 → Cloudflare DNS에 CNAME 추가 (도메인 구매 필요)
