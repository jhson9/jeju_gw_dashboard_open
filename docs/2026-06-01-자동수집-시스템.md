## SSL 검증 우회

한국 공공기관 사이트는 KISA/GPKI 루트 CA 를 사용하는데, Python `certifi` 에 없어 SSLError 발생.

처리: `requests.get(... , verify=True)` 첫 시도 → `requests.exceptions.SSLError` 잡으면 → `urllib3.disable_warnings()` + `verify=False` 로 재시도.

브라우저는 OS 인증서 저장소를 쓰므로 정상 동작. 단일 도메인 공공 데이터 조회라 MITM 위험 낮음.

## 트러블슈팅 — 오늘 발견한 함정

### 1. 400 Bad Request (selectObsvEachList.json)
- 원인: `sensorCb=S11` 로 보냈는데 실제 키는 `mSns=S11`
- 진단: 브라우저 검색 버튼 클릭 시 네트워크 요청 body 캡처 → 9개 정식 파라미터 확인

### 2. SSL Error (CERTIFICATE_VERIFY_FAILED)
- 원인: 한국 정부 루트 CA가 Python certifi에 없음
- 처리: `verify=False` 자동 폴백 + urllib3 경고 억제

### 3. 5월 데이터가 04.지하수위 탭에 안 보임 (단계별 누락)
1차 누락: collector 가 `by_station_month/` 에만 저장 → 04.지하수위 탭은 `by_station/` (legacy) 에서 읽음 → 둘 다 갱신하도록 미러 저장 추가
2차 누락: `by_station/` 갱신은 됐지만 `by_watershed/` 가 stale → collector 가 month 후 자동으로 `watershed_mapper.run_watershed_pipeline()` 호출하도록 추가

데이터 흐름 도식(위) 의 모든 화살표가 자동으로 흐르는지 확인 필수.

### 4. Month CSV 날짜 포맷 불일치
- 신규 행: `'2026-05'` (API 원본)
- 기존 행: `'2026-04-01'` (legacy 포맷)
- 해결: `_normalize_month_date()` 함수로 `'YYYY-MM-01'` 통일 + `merge_and_save` 가 기존 bad 행도 정규화

### 5. PW가시1 빈 응답
- API 가 `result=success, list=[]` 반환
- 원인: 양수시험정(PW prefix)은 비정기 측정 — 데이터 자체가 없음
- 처리: collector 가 빈 응답을 정상 처리 (실패로 기록 안 함)
